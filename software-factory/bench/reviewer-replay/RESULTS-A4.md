# Results — A.4 reviewer execution-evidence replay, n = 18

**Pre-registration:** [`PRE-REGISTRATION-A4.md`](PRE-REGISTRATION-A4.md), committed
before any paid call (`5a037d74`). Every table below is a cell that file fixed in
advance.

**Verdict up front: do not ship A.4 as specified. The treatment made the
Reviewer *worse*, in every one of nine replicate pairings, and the mechanism is
visible in the Reviewer's own findings.** The effect is not statistically
significant at this n and this experiment could not have made it so — see the
MDE. Spend: **$1.2693**.

---

## 1. The headline

| arm | correct / 18 | accuracy | 95% CI (Clopper-Pearson) | TP | FP | FN | TN | precision | recall |
|---|---|---|---|---|---|---|---|---|---|
| archived recording (what production actually did) | 8 | 44.4% | [21.5%, 69.2%] | 6 | 9 | 1 | 2 | 40.0% | 85.7% |
| **control**, replicate 1 (primary) | **11** | **61.1%** | [35.7%, 82.7%] | 6 | 6 | 1 | 5 | 50.0% | 85.7% |
| **treatment**, replicate 1 (primary) | **8** | **44.4%** | [21.5%, 69.2%] | 6 | 9 | 1 | 2 | 40.0% | 85.7% |

`Δ accuracy = −16.7 pp` (treatment minus control).

**Paired McNemar, exact, two-sided, on replicate 1:** 3 instances where control
was right and treatment wrong, **0** the other way. `p = 0.25`. Not significant.

The two CIs overlap almost entirely. At n = 18 they were always going to.

## 2. The premise this measurement corrects

**The Reviewer was never fed diff text only.** All 31 graded-sweep reviewer calls
already carry a `## Latest test output` section. What it carries is
`story.dev_attempts_json[-1].test_output_tail` — **the Dev's own report of its
own final run**, 491–1,894 bytes, ANSI intact, under a `run_verdict=PASSED`
header — against a `## PR diff` of 2,053–56,040 bytes.

So the treatment tested here is not "add execution output". It is **replace the
Dev's self-reported green tail with the sandbox runtime's own transcript of every
command the Dev ran, and tell the Reviewer the transcript outranks the Dev's
artefacts.** Anyone quoting this result must quote that framing with it.

## 3. Control-arm fidelity — reported before any comparison

| replicate | reproduces the archived verdict on |
|---|---|
| control rep 1 | 15 / 18 |
| control rep 2 | 17 / 18 |
| control rep 3 | 15 / 18 |

Fidelity ≥ 12/18 on every replicate, so the pre-registered "measure differently"
condition did **not** trigger and the C↔T comparison is reportable.

But the residual is not replay error — it is the Reviewer's own
nondeterminism. Production passes no temperature and neither does this replay,
so the same bytes do not yield the same verdict:

| arm | pairwise self-agreement across replicates | accuracy across replicates |
|---|---|---|
| control | 16/18, 14/18, 14/18 | 11, 9, 9 |
| **treatment** | **18/18, 18/18, 18/18** | **8, 8, 8** |

**The control's within-arm accuracy swings by 2 instances (11 pp) on identical
input.** That is the same order as the effect being measured, which is why the
cross-replicate table in §5 matters more than the single primary comparison.

Note the second-order finding, which is not noise: **the treatment is perfectly
deterministic and the control is not.** Adding the transcript plus an explicit
precedence rule collapses the Reviewer onto one answer, three times out of three,
on all 18 instances. More confident. Less accurate.

## 6. Why it got worse — the mechanism, in the Reviewer's own words

This is the part that changes the design, not the p-value.

On the three instances the treatment flipped from `request_changes` to `approve`,
the control's blocking findings were **substantively right** — the oracle says
none of the three is resolved — and the treatment discarded them, citing the
green transcript.

| instance | control (correct: block) | treatment (wrong: approve) |
|---|---|---|
| `alibaba__opensandbox-816` | `test_quality_score` **0.45**; *"the new tests only codify the implementation's blanket symlink rejection and never cover the required realpath-based allowlist behavior"* | `test_quality_score` **0.86**; *"The targeted and regression test runs **shown in the transcript** are green and meaningful for this story."* |
| `pyinfra-dev__pyinfra-1665` | **0.72**; *"the new test still uses `OSError` instead of the story's `SSHException` failure mode, so it does not prove the reboot/disconnect regression is fixed"* | **0.84**; *"The revised test is meaningfully stronger than in the prior review because it now proves both cleanup attempts are made"* |
| `vyperlang__vyper-4801` | **0.64**; *"the added coverage is too weak/self-confirming, this should not ship yet"* | **0.88**; *"The targeted venom suite **ran green** after the changes, and the added tests are meaningful enough to support the fix"* |

The aggregate moves the same way:

| arm | approvals / 18 | mean `test_quality_score` | findings raised, 54 calls |
|---|---|---|---|
| control | 12, 14, 14 | 0.819 / 0.849 / 0.864 | **26** |
| treatment | 15, 15, 15 | 0.852 / 0.861 / 0.860 | **11** |

**The treatment cut the Reviewer's findings by 58% and raised its self-assessed
test-quality score.** It did not make the Reviewer sharper; it gave it a reason
to stop looking.

### The root cause is an independence error in A.4's own design

The transcript is independent of the Dev's **narration**. It is not independent
of the Dev's **choices**. Every command in it was chosen and run by the party
under review, and a Dev on a run-until-green loop stops as soon as the tests it
wrote pass. So the transcript's terminal state is *green, by construction* — and
the pre-registered precedence rule ("when the transcript disagrees with the
self-summary or the diff, the transcript wins") instructs the Reviewer to let
that green outrank its own reading of whether the tests mean anything.

That is the exact defect `SWE-bench failure synthesis (2026-08-02)` already
recorded on this reviewer: *"the review loop is inert: it approves 0.9+ because
dev's tests are self-confirming."* **A.4 as specified feeds that failure mode
more of what causes it.**

P7's 42% → 72% is a judge shown execution output from an **oracle-side harness
run over a fixed candidate**. Ours is a judge shown the **author's own run
history**. Those are different variables with the same name. This result does not
refute P7; it says the corpus we have cannot supply P7's independent variable,
and the nearest available substitute has the opposite sign.

### 6.1 Alternative explanations I cannot rule out at this n

An adversarial pass on the paragraph above. Each of these would produce the same
table, and this experiment cannot separate them.

1. **The treatment is one splice but three simultaneous changes**: it *removes*
   the Dev's self-reported tail, *adds* the transcript, and *adds* the precedence
   rule. The pre-registration fixed it as a single arm (correctly — that is what
   would ship), so **none of the three is individually attributable.** The
   mechanism in §6 is read off the Reviewer's own prose, which points at the
   precedence rule and the green transcript; it is not established by a
   factorial design.
2. **Length is a confound.** Treatment prompts run 27k–97k chars against
   17k–75k for control. "Longer prompt ⇒ more approvals" would look identical.
   Weak evidence against it: the two largest additions (`tox` +23.6k,
   `idaholab` +24.7k) did **not** flip toward approve, while the three flips were
   the +15k to +19k range. Not decisive.
3. **Model drift.** The graded sweep ran 2026-08-03/04; this replay ran
   2026-08-05 against the same Azure deployment name. A deployment-side change
   would show up as control-arm infidelity — which is 15–17/18, consistent with
   temperature alone, but not proof.
4. **Only the negative class moved.** Recall is 6/7 in every arm and every
   replicate; the entire effect is in false approvals. Any conclusion here is
   about precision only.

## 7. Statistical honesty — what this design could and could not detect

Stated in the pre-registration, restated here because it bounds everything above.

- n = 18, paired. **One instance flipping is 5.6 pp.** A 4-instance swing is
  22 pp and is *not* "42% → 72% reproduced".
- For McNemar exact two-sided at `p < 0.05`, you need **6 discordant pairs all
  falling the same way** (`6-0` → `p = 0.031`; `5-1` → `p = 0.219`). The
  smallest detectable significant effect is therefore **±33 pp, almost perfectly
  one-directional**.
- Consequently: **this experiment could return a green light or a null. It could
  never return a defensible small positive**, and it cannot certify the observed
  −16.7 pp as real either. What it *can* do — and did — is rule out a large
  positive, which is the decision A.4 was waiting on.
- The Reviewer's own nondeterminism (±2 instances, 11 pp, on byte-identical
  input) sits inside the confidence interval. Treat every single-replicate number
  in this file as ±2 instances.
- **Reported effect: directional negative, consistent in sign across all nine
  pairings, not statistically significant.** Not "the treatment is 16.7 pp
  worse".

## 9. Recommendation to the operator

**Do not ship A.4 as `PLAN.md` specifies it.** Specifically:

1. **Do not** attach the Dev's own run history to the reviewer prompt, and **do
   not** add a precedence rule that makes any Dev-produced execution artefact
   outrank the Reviewer's own reading. Measured: 9 of 9 pairings worse, findings
   down 58%, self-assessed test quality up. The mechanism is understood, not
   just observed.
2. **Correct `PLAN.md` A.4's premise.** It says the reviewer's view is diff
   **text**; the archive says it is diff text *plus the Dev's self-reported test
   tail*. A.4's "the `output_tail` plumbing exists on the gate path" note reads
   as though that plumbing is missing from review. It is not — it is already
   there, and it is the problem.
3. **The half of A.4 worth keeping is the half this corpus cannot test:** a
   **harness-run** result, produced by something the Dev does not control, on the
   final patch, before the Reviewer sees it. That is a real independent variable
   and it is what P7 actually measured. It needs the gate path to run and persist
   an independent result, which is A.7/A.5 work, not a prompt change.
4. **If A.4-with-a-real-harness-run is later built, do not re-run this
   experiment at n = 18.** §7 shows the design cannot resolve anything under
   ±33 pp. Widening to the n needed is the same money problem `PLAN.md` P8
   already costs out. Judge it on the negative-side metric instead: this replay
   found *precision* is the whole problem (9 FP, 1 FN, recall 85.7% in every
   arm and replicate), so the target is "does it block PRs the oracle says are
   broken", and `alibaba` / `pyinfra` / `vyper` / `conan-19750` /
   `harumiweb` / `tox` / `ucfopen` / `rapid-mlx` / `conan-19735` are the nine
   instances that matter.
5. **Worth a separate look, unprompted by A.4:** the control replay scored
   **11/18** where the recorded production run scored **8/18** on the same bytes.
   Three of production's nine false approvals are recoverable by nothing but a
   re-roll. That points at `k > 1` on the reviewer — cheap, and orthogonal to
   A.4 — but it is an observation from three replicates, not a measurement.

## 10. Deviations from the pre-registration — all of them

1. **Redaction extended once, before any paid call.** The pre-registered rule
   `/…/swebench-work/[component]` did not match a bare
   `find /home/k/.cache/swebench-work` with no trailing component (one
   occurrence, `line__line-bot-sdk-python-981_interface`). The regex now accepts
   an optional trailing component. Deterministic, applied uniformly to both the
   evidence block and the provenance haystack.
2. **Redaction does not remove SWE-bench instance ids**, which survive in 5 of 18
   evidence blocks via story-file paths the Dev viewed. **This is immaterial, and
   for a reason worth recording separately: the control prompt already names the
   instance**, because the `## Story` section's heading is literally
   `# <instance_id>` on all 18. So instance identity is not a channel the
   treatment adds — it is a channel *both* arms have, and a contamination note
   about the graded sweep itself rather than about this splice.
3. **`FileEditorObservation` fields were read from the wrong row initially**, so
   the first build produced `EDIT edit` with no path. Fixed before any paid call;
   the pre-registration says the spine must make edit-after-a-red-run visible and
   it now does.
4. **Zero treatment iterations.** One treatment was specified, one was built, one
   was run, and its number is reported. Nothing was tuned after seeing a result.

## 11. What could not be done honestly

- **A genuinely independent execution run is not in this corpus.** The bench
  sweep records the Dev's sandbox sessions and the oracle's post-hoc grade, and
  nothing in between. Constructing an independent harness result would have meant
  either running the oracle's tests (leaking `FAIL_TO_PASS` into the input) or
  fabricating a run. Neither was done. **The treatment therefore tests
  "independent of the Dev's narration", not "independent of the Dev".** That gap
  is the finding, not a caveat on it.
- **n = 18 cannot be widened from archived prompts.** 31 reviewer calls exist but
  only the last per instance carries a label the oracle earned, and one instance
  never reached review. Scoring the other 13 would score intermediate states the
  oracle never graded.
- **`getmoto__moto-9841` is unexplained.** It is the one oracle-resolved PR that
  every arm and every replicate blocks. Neither arm's findings were checked
  against the gold patch, because doing so is exactly the oracle-as-input error
  this file spent §7 of its pre-registration forbidding.

## Reproducing

```bash
uv sync --all-extras
# $0 — reproduces the pre-change baseline from the committed archive.
uv run python bench/reviewer-replay/replay.py baseline
# $0 — builds both arms, runs every assertion, prints sizes.
uv run python bench/reviewer-replay/replay.py --out OUT build
# paid — ~$0.02-0.05/call.
uv run python bench/reviewer-replay/replay.py --out OUT run --arm control   --replicate 1
uv run python bench/reviewer-replay/replay.py --out OUT run --arm treatment --replicate 1
# $0 — scores whatever `run` produced.
uv run python bench/reviewer-replay/replay.py --out OUT analyze
```

`--corpus` defaults to `/home/k/sf-reviewer-corpus-2026-08-05/` and is
configurable; it is treated as read-only. The corpus is **not** in git — the live
path under `bench/swebench/runs/` is gitignored and `_reset_run_artifacts`
(`bench/swebench_adapter.py:1556`) wipes it at the top of every bench run, so
that backup is the only copy of the input to this measurement. The outputs are
committed under [`artifacts/`](artifacts/) so these numbers stay backed by artifacts
even if the corpus is lost — the failure that unbacked the n = 6 headline on
2026-08-02.

Harness tests: `tests/test_reviewer_replay.py` (splice boundaries, the
oracle-leakage tripwires, provenance-by-construction, Clopper-Pearson against
published values, McNemar against hand computation).
